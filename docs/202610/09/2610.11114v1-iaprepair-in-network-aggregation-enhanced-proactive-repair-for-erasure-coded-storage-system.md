## 摘要
纠删码存储以远低于完全复制的存储开销提供容错能力，但修复丢失或处于风险中的块需要密集的跨节点数据传输。现有反应式修复方案仅在故障发生后才启动，而主动式方案虽能在故障前迁移数据，但通常将迁移、重构和网络聚合视为松耦合的操作。因此，接收端瓶颈、异构可用带宽以及有限的可编程交换机状态仍制约着修复并行度。本文提出 IAPRepair，一种面向纠删码存储的网内聚合增强主动修复框架。IAPRepair 联合构建每个修复批次，根据归一化传输负载分配重构提供者和替换节点，围绕剩余接收容量调度迁移，并对否则会使健康节点过载的重构块选择性启用网内聚合。这种选择性设计减少了接收端流量，同时保留迁移并行度，并遵守可配置的交换机资源预算。我们使用 Tofino 可编程交换机和 16 个存储节点实现了 IAPRepair，并利用原型测试平台和大规模仿真对其进行评估。在不同编码参数、块大小、节点规模以及多种 STF 节点场景下，与所评估的先进方法相比，IAPRepair 将修复时间至少减少 47.83%。结果表明，将主动修复决策与网内处理相协调，是在带宽异构条件下提高修复效率的有效途径。

## Abstract
Erasure-coded storage provides fault tolerance with substantially lower storage overhead than full replication, but repairing lost or at-risk blocks requires intensive cross-node data transfer. Existing reactive repair schemes start only after a failure, while proactive schemes can move data before failure but commonly treat migration, reconstruction, and network aggregation as loosely coupled operations. As a result, receiver?side bottlenecks, heterogeneous available bandwidth, and limited programmable-switch state continue to constrain repair paral?lelism. This paper presents IAPRepair, an in-network aggre?gation enhanced proactive repair framework for erasure-coded storage. IAPRepair jointly constructs each repair batch, assigns reconstruction providers and replacement nodes according to normalized transmission loads, schedules migration around the remaining receive capacity, and selectively enables in-network aggregation for reconstruction blocks that would otherwise over?load healthy nodes. The selective design reduces receiver-side traffic while retaining migration parallelism and respecting a configurable switch-resource budget. We implement IAPRepair with a Tofino programmable switch and 16 storage nodes, and evaluate it using both a prototype testbed and large-scale simu?lations. Across coding parameters, block sizes, node populations, and multiple STF-node scenarios, IAPRepair reduces repair time by at least 47.83% compared with the evaluated state-of-the-art methods. The results demonstrate that coordinating proactive repair decisions with in-network processing is an effective way to improve repair efficiency under bandwidth heterogeneity.

## 1. 论文的核心问题与整体含义

### 研究背景
- **纠删码存储的普及与代价**：大规模分布式存储系统广泛采用纠删码（尤其是 Reed–Solomon 码，RS(n,k)）以远低于全复制的存储开销提供容错能力。但修复一个丢失或处于风险中的块需要从多个节点跨网络检索数据，节点故障会引发大量并发修复任务，跨节点流量显著延长数据不可用窗口，直接影响系统可靠性。
- **反应式修复的局限**：PR、PPT、PivotRepair、RepairBoost、SelectiveEC 等反应式方法仅在故障发生后才启动修复，无法利用故障预测带来的提前修复时间窗口。
- **主动式修复的不足**：基于故障预测的主动修复（如 FastPR、LFPR）可在节点失效前迁移数据，但通常将迁移、重建与网络聚合视为**松耦合操作**，未充分协调接收端容量、带宽异构性以及迁移与重建之间的选择。
- **核心矛盾——非对称流量模式**：STF（soon-to-fail，即将失效）节点和健康节点都可提供修复数据，但只有健康节点能接收修复块。并发的迁移与重建可能压垮少数健康接收节点；当节点可用带宽与前端负载共享且因节点而异时，问题进一步加剧——按块数均衡的调度方案在传输时间上仍可能严重失衡。
- **可编程交换机带来的机遇与挑战**：网内聚合（INA）可在转发路径上合并重建流量，减少送达存储节点的数据量。但现有 INA 修复系统（NetEC、Paint、InaPR）主要面向反应式修复。将 INA 应用于主动修复需回答两个耦合问题：**哪些重建块应消耗稀缺的交换机状态**？**在节点带宽异构时如何分配迁移与重建任务**？

### 整体含义
IAPRepair 提出一种**网内聚合增强的主动修复框架**，将迁移、重建与选择性网内聚合在同一修复批次内联合优化，在带宽异构条件下同时缓解接收端瓶颈、保留迁移并行度并遵守可配置的交换机资源预算。

## 2. 论文提出的方法论

### 核心思想
IAPRepair 在每个修复批次内协调三类决策：
1. **重建块选择与节点分配**：依据归一化的上行/下行负载，为每个重建块选定 k 个提供者节点和一个替换节点。
2. **迁移调度**：围绕健康节点的剩余接收容量安排迁移块，避免接收端过载。
3. **选择性网内聚合**：仅对否则会造成接收端瓶颈的重建块启用 INA，并限制其数量不超过交换机预算 θ。

### 系统架构
- **控制平面**：修复协调器依次执行重建选择、迁移分配、选择性 INA 决策，生成修复命令。
- **数据平面**：P4 可编程交换机解析 ACP 包（UDP 扩展，含 Type/Pid/Bid/Ver/Seq 字段），迁移包与未标记重建包直接转发，标记的重建包进入专用聚合器组。
- **聚合器设计**：每个启用 INA 的重建块分配一组聚合器（每组 Nₐ 个），维护 rCnt、rVer、rData 三个寄存器状态；同组共享 rNum。收到包后执行异或并递增 rCnt，当 rCnt=rNum 时输出聚合结果并复位。

### 问题建模
- 决策变量：φᵢ,ⱼ（健康节点 hᵢ 是否为重建块 sⱼ 提供数据）、ϕᵢ,ⱼ（hᵢ 是否为 sⱼ 的替换节点）、ψⱼ（sⱼ 是否启用 INA）。
- 约束条件：每个重建块需 k 个健康提供者；每个迁移块仅由 STF 节点提供；同一 stripe 的块须放置在不同节点；Σψⱼ ≤ θ。
- 目标函数（Eq. 16）：最大化每批次修复效率 (|Sm|+|Sr|)/t_bch，其中批次时间 t_bch 由发送时间 nᵤᵢ/uᵢ 与接收时间 nᵈᵢ/dᵢ 的最大值决定。

### 关键算法流程

**算法 1：重建块选择**
- 用 Eq. 17 计算每个 STF 块 sⱼ 的得分 scⱼ = Σᵢ∈Kmin(sⱼ) (nᵤᵢ+1)/uᵢ，其中 Kmin(sⱼ) 为 pro(sⱼ) 中负载最小的 k 个节点。
- 每次迭代选择得分最小的块加入 Sr，用 Eq. 18 选择接收负载最小的节点作为替换节点（并维护 Pᵢ 记录 stripe 已分配的替换节点）。
- 当负载均衡比 lᵤavg/lᵤmax ≥ ξ 时停止，每批重建块数上限为 2|Hh|。

**算法 2：迁移块选择**
- 用 Eq. 19、Eq. 20 计算每个 STF 节点的最大发送块数 Nᵤᵢ 与每个健康节点的最大接收迁移块数 Nᵐ,ᵈᵢ。
- 优先将迁移块集中分配到 Nᵐ,ᵈᵢ 最大的节点，以释放带宽供更多迁移使用（减少所需 INA 块数）。

- 每次迭代选择 (Nⁱⁿᵃᵢ − nⁱⁿᵃᵢ) 最大的节点，从其分配的替换块中随机选一个加入 Sina，直到满足所有节点需求或达到 θ。

### 复杂度
- 算法 1：O(2|Hh|²|S|)；算法 2：O(|S|(|Hh|+1))；算法 3：O(θ|Hh|)。

## 6. 论文的主要结论与发现

1. **修复时间显著降低**：在所有编码参数下，IAPRepair 相比 SelectiveEC 降低 47.83%–68.04%，相比 FastPR 降低 53.79%–65.49%，相比 Migration 降低 57.76%–75.94%。
2. **块大小影响**：随块大小增大各方法修复时间均上升，但 IAPRepair 平均比 SelectiveEC/FastPR/Migration 分别短 55.31%/61.97%/67.87%。
3. **节点规模影响**：节点数增加时 IAPRepair 修复时间平滑下降，能利用所有节点带宽；FastPR 呈阶梯状，Migration 受 STF 上行带宽限制不随节点数下降。
4. **多 STF 场景**：在 1/2/3 个 STF 节点下，IAPRepair 分别降低 53.84%/49.09%/36.79% 修复时间。
5. **ξ 参数**：修复时间随 ξ 先降后升，最佳区间为 0.9–0.95；ξ 过大会使批次时间过长、网络状态过期。
6. **故障鲁棒性**：STF 节点在修复中途失效时，IAPRepair 仍能完成修复；k 越小对失效时间越敏感。
7. **LRC 泛化性**：在 LRC(6,4,2)/(8,6,2)/(10,8,2) 下降低修复时间 29.79%–69.65%。
8. **消融结论**：节点数与编码参数接近时，块选择算法贡献更大；节点数远大于编码参数时，INA 贡献更大；两者结合效果最优。
9. **资源与开销**：SRAM 各 stage 占用低于 15.00%，TCAM 开销可忽略；算法运行时小于 1 秒，可隐藏于数据传输时间内。

- **联合优化框架**：将批次构建、节点分配、迁移调度与选择性 INA 纳入同一优化目标，而非各自独立决策。

- **理论建模完整**：给出决策变量、约束、目标函数及三个算法的复杂度分析。
- **实现落地扎实**：在真实 Tofino 交换机与 16 存储节点上实现原型，而非纯仿真；并给出详细的交换机各 stage 资源占用表。
- **泛化性验证**：同时验证 RS 与 LRC 两类生产常用纠删码，并给出 LRC 下的适配策略。
- **运行时开销低**：基于块评分的启发式算法复杂度低，运行时间远优于需反复调用最大流算法的 SelectiveEC/FastPR。

## 8. 不足与局限

- **实验规模受限**：原型仅 16 个存储节点，大规模结论主要依赖仿真，真实生产环境（单节点超 150 万块）下的表现未直接验证。
- **对比方法有限**：未与 NetEC、Paint、InaPR 等 INA 类修复方案直接对比，也未与更多主动修复方案（如 LFPR）对比，削弱了 INA 维度的横向说服力。
- **多 STF 场景覆盖不足**：受 RS(9,6) 限制，STF 节点数仅测试 1–3 个；更多节点同时失效的极端场景未评估。
